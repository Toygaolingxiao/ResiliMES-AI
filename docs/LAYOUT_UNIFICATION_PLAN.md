## 一、审查结论：不是「一套系统有偏差」，是三套视觉语言并存

三路合计 49 条发现（高 9 / 中 24 / 低 16；timeline 独立体系等问题在两路中重复计数）。归并后是四个结构性事实：

**事实 1：全站有三套视觉语言。**
- 控制台外壳（styles.css 1331 行 + fab.css 293 行）：Carbon 令牌 + IBM Plex，最完整，但自家漂移也不少（见事实 3）。
- report/import（report.css 125 行）：颜色「值」与基线同源，但「引用」全是字面量；840px 定宽文档骨架（源于可打印定位）。
- **timeline（timeline.css 216 行 + timeline.js）：整套第二系统**——自立 Slate 色板（同名令牌不同值：`--ink #1e293b` 对基线 `#161616`）、字体不用 IBM Plex（Avenir Next 栈、无 @font-face）、圆角 4/6px（基线 0/2px）、主按钮是墨黑而非 accent 蓝、无深色主题、无焦点样式；同一套色板还在 timeline.js 里以 canvas 填充色再写一份，构成第三来源。其文件头注释自陈「Chrome is not the console theme」——例外是有意的，但基线文档从未登记，与执行标准「文档与代码不一致视为缺陷」直接冲突。

**事实 2：证据档位徽标（記録 / 観測帰因 / 不明）全站四种貌。**
report/import 陈述行是标杆貌（`.tier`）；同两页的覆盖率列表只挂子类不挂基类，几何全无；控制台 AI 面板降级为无档位色的通用 `.chip`；cases 页根本不渲染档位；evidence/explanation/quality/replay 四个模块 grep 不到档位渲染。对照：严重度徽标 `.sev` 是全仓唯一「基线色对 → var() 引用 → 单一渲染路径」完整落地的徽标——证明收敛做得到，只是没做完。

**事实 3：基线令牌立了但没人引用。**
- 间距阶梯 `--s1..s4`（4/8/12/16px）：styles.css 仅引用 4 次，其余三文件 0 次；实际间距数值里 6px（styles 中 25 次）、10px（18 次）比基线最大档还高频。report 页 `.sheet` 内边距 28/32/40px 整组在基线之外——**标杆页自身未收敛**。
- 颜色：四文件并集 80 种 hex + 13 种 rgba；定义外硬编码 CSS 112 处、JS 73 处。同义多值：完成绿有 3 个（`--good #198038` / `.pill` 的 `#a7f0ba` 对 / `#24a148`）、运行蓝 3 个、琥珀警告文字 `#684e00` 全仓无令牌定义却用了 5 处。
- #117 的标杆新代码同样如此：report.css 里 `#a2191f`（警戒色）硬编码 4 处、`#0f62fe` 硬编码 2 处——值对齐了，引用方式没对齐，因为 report.css 的 `:root` 里根本没有这两个令牌。
- 断点：基线明定五档「不另发明」，fab.css 自加 1200、timeline.css 自加 720、report.css 无任何宽度断点。字阶：fab.css 有 11.5px×9、12.5px×8 两档「半像素」字号；report 正文 15px、h1 22px 均在字阶外。
- `.swatch` 在 styles.css 内被定义两次且互相覆盖（图例圆点实际渲染成矩形，按层叠规则推演，未实机验）。

**事实 4：状态纪律两套并行，且有一处新的功能性静默失败。**
- 明示截断（timeline 的 scope 明示句、cases 的上限余数、import 的 shown/total）与静默截断（quality 三处 slice 无余数、fab 三处 slice 无计数）同站并存。
- i18n 目录本身完整（实测 1025 键 × 三语、缺失 0），但回退政策四套（回退日文 / 回退英文 / 回退英文常量 / 返回空串）；SMT 模式整卡硬编码英文、常显英文长句，与「来源标注紧凑、按需」的订正原则相悖；时长格式全站三套（console 本地化版、timeline 紧凑版、fab 恒英文版）。
- **控制台主流程失败完全静默**：console.js 的 run() catch 把错误写进状态行，finally 的 paint() 随即在「未运行且无报告」时把状态行置空——全站最核心的动作（场景重排）失败后错误被擦除、无提示、无重试入口。代码路径确定，非推断。
- /report 加载无在途防护（无 seq token、按钮不禁用），慢的旧请求可覆盖新结果（基于代码结构的推断）；/import 内容表双重截断且原文在页面上不可达；质量信任视图每卡常显出处注，与订正原则相悖（长注留一份即可）。

## 三、目标设计系统 v1（收敛终态）

**令牌层**
- 一份全站令牌源：四个 CSS 文件与 JS 色板都从同一组 `--*` 令牌取值；CSS 定义外硬编码 hex/rgba 归零（图表数据色除外，登记为图表色板）；JS 的 AREA_TONE / STATE_COLOR / timeline canvas 色板改为引用同一来源（构建时常量或 CSS 变量读取，二选一写死）。
- 同义同值：完成绿、运行蓝、警戒红、琥珀文字各只剩一个值；`#684e00` 做决策（登记为 `--amber-ink` 或改用 `--amber`）；死令牌（`--hot`、`--serif`、`--s1` 等零引用项）删除或启用。

**间距与字阶**
- 间距只允许 0 与 4/8/12/16px 且必须 var() 引用；组件级固定值登记为例外清单：卡片内边距 12px 14px、页面容器 12px 16px、表格单元格 6px 8px、控件 4px 8px、文档页（sheet）24px 32px 一档。
- 字号只允许 `--text-*` 六档；清除 11.5/12.5/15/22px 等表外值；行高收敛为 1.43（应用）/ 1.5（文档）两值并登记。

**断点与主题**
- 断点回归基线五档（1500/1440/1320/1279/1023）；fab 的 1200、timeline 的 720 并入最接近的既有档；report 至少补 1023 一档；`@media print` 与 `prefers-reduced-motion` 列为每页必备。
- report/import/timeline 补齐主题初始化与深色令牌、全局 `:focus-visible`；timeline 接入 IBM Plex。

**组件层（每组件唯一实现，详见附录 B 收敛表）**
主按钮 `.run`、幽灵按钮 `.run.quiet`、语言切换 `.langs button`、输入框两型（控制台下划线式 / 表单盒式，边线统一 `--field-line`、radius 0）、字段校验 `.field-error`（先令牌化再推广）、表格 `table`（含 `.compare`；`.fx-table` 并入，`.contents-table` 为导入变体）、档位徽标 `.tier`（全站唯一貌，cases 证据列补齐）、严重度 `.sev`（已收敛）、verdict `.pill`（色值令牌化）、度量卡 `.kpi`、一般卡片 `.card`、浮层收敛为 tooltip/菜单/面板三规格、状态点 `.lamp`、图例先消除 `.swatch` 双定义再拆名。

**骨架层（独立页与 panel 页同构）**
顶栏（48px、底边线、左品牌/返回+页面名、右语言+主题）→ 页面标题（应用页 `--text-title` 一档；文档页大一档须登记）→ 筛选区（一页一个，标签上置，操作按钮固定在末尾或右下独立行）→ 状态行（一页一条 `role="status"`，筛选区与内容区之间；来源行并入状态行或详情，不再单列）→ 内容区（卡片/表格容器统一 1px `var(--line)` 边、radius 0）→ 空/错误状态块（统一容器，沿用控制台 `.empty` 形态）。「返回」语义全站一致（回控制台为唯一默认，父子页关系写进顶栏面包屑而非同名异指的 `.back`）。

**状态层（八条统一规范）**
1. 状态双通道：`role="status"` 与 `role="alert"` 各一；成功失败都落字，禁止静默成功与静默失败；重绘不得覆盖未被看到的错误。
2. 加载三件套：文案 + 进度或量级 + 取消/超时去向；超 10 秒操作给量级提示；全站 fetch 统一 seq token + 在途禁用。
3. 空状态三段式：是什么空、为什么空、补什么不空；禁用单词式空态。
4. 错误四要素：本地化说明（服务器原文只进可展开详情）、影响范围、下一步动作、旧数据在屏标「未更新」。
5. 截断必明示：凡 slice/上限/省略号，同屏给「显示 X / 共 Y」或展开路径；单元格截断必须有详情承载。
6. 校验范式即 #117 基线（见标杆清单），域以服务端为准。
7. i18n 单一回退：缺键回退英文；时长/单位只用一套本地化格式器（以 console `formatDuration` 为基准合并其余两套）；服务器字符串未命中本地化白名单时原文显示但不吞理由。
8. 无障碍底线：全站共用 `:focus-visible`；状态有文字或形态冗余，颜色只作加强；关键信息不得只在 hover/title/SVG title 中。

## 四、波次规划（WIP=1，每波 1–3 个 PR，每个 PR 一种收敛）

### 波次 0：基线修订与决策（纯文档，1 个 PR）
- `docs/DESIGN_SYSTEM.md` 升 v1：写入第三节的收敛终态；逐项处置与代码的已知不一致（timeline 例外、report 行高/字号、间距例外清单）。
- 需要所有者拍板的决策点（见第六节）在此波次定版；未定的不进后续波次。
- 验收：v1 文档与本规划第三节逐条对应；决策点全部有结论或明确标「暂缓+理由」。

### 波次 1：令牌层收敛（零视觉变化优先，2–3 个 PR）
- PR-1a：report.css 令牌化——`:root` 补 `--alarm-ink`/`--accent` 等缺失令牌，4+2 处硬编码改 var()；`.tier` 色值改令牌引用。验收：像素级无变化（截图对比），grep 定义外 hex 在 report.css 归零。
- PR-1b：styles.css/fab.css 同义色收敛——完成绿、运行蓝、`#f1c21b`、`#ffb3b8` 等改令牌；`.swatch` 双定义拆名修复；死令牌清理。验收：同上 + 深色主题逐项核对。
- PR-1c：JS 色板单源化——console.js AREA_TONE、overview.js STATE_COLOR 系、timeline.js canvas 色板改引用令牌源。验收：图表渲染截图对比无变化（数据色登记保留的除外）。
- 依赖：波次 0 的 `#684e00` 决策先行。

### 波次 2：组件收敛（每组件一 PR，约 5–6 个 PR）
顺序按「全站出镜率 × 分歧度」：① 档位徽标 `.tier` 全站唯一貌（coverage 列表补基类、控制台 `.chip.ctx-tier` 改挂 `.tier`、cases 证据列补渲染 + 契约测试）；② 主/次按钮与语言切换（三页并入 `.run`/`.run.quiet`/`.langs`，report 提交按钮改 var(--accent)，timeline 主按钮改 accent）；③ 输入框两型定版 + `.field-error` 推广到 timeline 筛选与 import；④ 表格（`.fx-table` 并入通式、`.contents-table` 字号对齐、数字列右对齐全站有效、`.num` 只留一个定义）；⑤ 徽标族（`.pill` 令牌化、`.fx-pill` 色值令牌化、`.fx-badge` 并入 `.badge`、`.fx-reason` 字号入阶）；⑥ 卡片与浮层（`.fx-card`/`.tl-stat` 几何并入 `.card`/`.kpi`；tooltip/菜单/面板三规格收敛，阴影统一一档）。
- 每 PR 验收：该组件全站只剩一种实现（grep 类名可证），受影响页面截图对比除预期项外无变化，契约测试覆盖渲染路径。

### 波次 3：页面骨架统一（每页一 PR，约 4 个 PR）
- PR-3a timeline：接入 styles 令牌与 IBM Plex（仅页面 chrome，甘特数据色按波次 0 决策登记保留）、补顶栏/主题/焦点、三行状态收为一条、断点 720 并入基线档、筛选表单改标签上置与统一输入型。

- PR-3c 控制台内部：panel 滚动模型统一（recover 的破格与 fab 的负边距贴边收敛）、`.sheet` 同名异义改名、详情面板三模型收敛为波次 0 定的规格。
- PR-3d fab 视图：字号入阶（11.5→12、12.5→13）、1200 断点并入、`.fx-*` 组件按波次 2 的收敛结果对齐。
- 验收：每页骨架区块顺序与第三节一致（可用 DOM 结构测试断言）；窄幅（1023 档）与深色逐页走查。

### 波次 4：状态与文案纪律（约 4–5 个 PR，其中 4a 为 P0 先行）
- PR-4a修主流程静默失败：run() 的错误进状态模型持久呈现 + 重试入口；控制台 init 补错误态（H1、M9）。

- PR-4d：i18n 收敛：单一回退政策（回退英文）、硬编码字符串键化（SMT 整卡英文、banner 整句、单位后缀）、切语言重绘浮层、时长格式器三合一、数字格式 locale 统一。
- PR-4e：出处文案收敛（按所有者订正原则）：quality 每卡出处注收为一份、report.slow 常显句收进加载态、SMT 英文长句收进详情、控制台 banner 句式与语言合规化。
- 验收：状态八规范逐条有对应测试或走查记录；三语逐页切换无残留外语（服务器原文白名单除外且有标注）。

### 波次 5：验收与防回潮（1 个 PR + 一次实机复审）
- 自动守卫：CSS 侧检查（定义外 hex、表外字号/间距字面量、基线外断点）进 CI 或契约测试；档位徽标渲染、i18n 回退政策各有契约测试。
- 实机复审：按章程验收门——运行实例逐页、三语、两档宽度 + 1023 窄幅、深色，零高发现、中发现或修或在 epic 显式豁免；全量测试绿且不少于届时计数。
- `docs/DESIGN_SYSTEM.md` v1 与代码一致性复核（文档与代码不一致视为缺陷，此后同样适用于本规划）。

## 六、需要所有者拍板的决策点（波次 0 定版）

1. **timeline 的 chrome 是否并入全站系统**：其独立体系源于 Schedule Viewer 移植（文件头注释自陈）。建议：页面 chrome（顶栏、字体、令牌、按钮、焦点、主题）并入，甘特图内部数据色板登记为「图表色板」保留——合流的是外壳，不是数据色。若整体保留例外，则须在基线中登记为例外页并写明边界。
2. **间距 6px/10px 的处置**：按基线清零（改动面大、无视觉收益风险低但工作量实），还是扩基线为六档（4/6/8/10/12/16）？建议扩档并强制 var() 引用——现状的高频值是事实上的系统，追认并管起来，比清零更省且不丢密度。
3. **`#684e00` 琥珀文字**：登记为 `--amber-ink`（其对比度据审查推断高于现 `--amber` 的边界值 4.52:1）还是并入 `--amber`？建议登记新令牌并重算对比度后定版。
4. **详情面板模型**：浮层（控制台 ctx-panel）/ 悬停（timeline tip）/ 行内展开（cases）三选一为全站默认，其余登记为场景例外。建议：行内展开为默认（不遮挡、可聚焦、打印友好），浮层仅保留给甘特条这类画布内对象。
5. **report 的文档骨架**：840px 定宽 + 打印定位是否保留？建议保留（功能定位差异），但顶栏、表单、按钮、状态行等共享组件与全站同构——统一的是组件，不是整页骨架。

## 七、非目标

- 不动排程核心与任何契约语义；呈现层所需的载荷字段只做加法。
- 不做一次性大重写：全部波次按 PR 粒度推进，任一 PR 可独立回滚；任一时刻在制只推进一项（WIP=1）。
- 图表内部的数据色（甘特条、热力格、泳道）不在「同义同值」范围，只要求来源单一、登记在册。
- 窄幅（约 400px）实机验证列入波次 5 复审，不在本规划内承诺移动端形态。
