# ResiliTrace · 项目总结、商业分析与完整方案

整理于 2026-11-11 · 依据《ResiliTrace 概念与架构蓝图 v2》。蓝图中的数字（71 / 486.7 / 82.12%、759 测试、复演 1/12）均取自该页；我没有仓库访问权，未能独立复核。

## 0. 结论先行

- **值得做，但理由要换一个。** 蓝图把产品押在“解释层”上；真正稀缺的是它的信任纪律：三档契约、事实核查门、“不明”即功能。在 LLM 时代，“敢说不知道，且每句话都能落到原始数据行”是少见的差异点。
- **离“可商用”还差最关键的一道验证：所有证据都来自仿真孪生，没有一条来自真实工厂。** 第 0 步验收的 71 / 486.7 / 82.12% 证明的是“基线可复现”（排程器的指标），不是“解释层有人愿意付费”。
- **最大内部短板是再演（1/12），最大外部风险是数据。** 第三方模式的主档位是「観測帰因」，而最硬的「記録」档恰好是第三方拿不到的。
- **我的建议四条：** ① 把“只建不推”改成“不对外宣称，但立刻对外访谈”；② 把仿真的弱点变成资产——用已知真值的故障注入做基准；③ MVP 收敛为 导入 → 异常一览 → 证据 → 报告 + 品质，再演降为 Beta；④ 先卖“诊断型 PoC”，再谈产品授权。

## 1. 蓝图总结

- **定位：** 不做排程器，做装在一切排程与 MES 结果之上的证据层，让每次排程决定都能被追问、查证、复演。滩头堡是半导体 fab 的排程异常归因。
- **是：** 给要为排程结果负责的人（半夜被问“为什么晚了”的人）；系统中立（别家排程器、老 MES 的结果也能查）；事后归因与回放；Guardrailed Autonomy 的产品化身（AI 只讲述，决定权在确定性系统）。
- **不是（定位纪律）：** 不是排程器；不说已在本番产线运行；不是实时系统；不给弱数字换说法（1/12 就写 1/12，并配口径）。
- **理念六条：** 证据先于叙述 · 「不明」是功能 · 决定归系统、解释归证据 · 系统中立 · 可复演才可信 · 为凌晨三点的人设计。每条自带判定标准，可直接用于设计评审。
- **三档契约：** 記録（决策记录里白纸黑字）／ 観測帰因（从痕迹反推，标明是推断）／ 不明（证据不足，并指出缺什么）。
- **架构：** resilimes/explain 包内六部件——导入校验、Evidence Schema、归因引擎、再演引擎、讲述层、事实核查门；三类数据源（自家孪生记录、MES 风格文件、第三方结果数据）；工房区（smt 孪生、engines、agents 冻结、insight）只经“运行记录”一条接口供数。
- **流程八步：** 导入 → 校验证据化 → 异常分诊 → 证据时间线（★）→ 再演或直接成稿 → 解说生成 → 事实核查门 → 报告导出，全程留痕，品质页自动更新。
- **页面六个：** 产品区 异常一览 / 证据 / 再演 / 品质；工房区 运行 / 总览。
- **状态：** 第 0 步已验收；1A 地基（Evidence Schema v0 → explain 骨架 → 证据页）为下一件；1B 本体；Phase 2 派工线后置。明确不做：账号计费、实时流、派工功能、通用 BI；正式定名前要核查商标与域名。

## 2. 商业分析（客观版）

### 2.1 成立的地方

1. **痛点具体。** “数小时翻日志”压成“打开页面就有”，场景清晰。但蓝图没有给出实测耗时，这个数要在访谈里量出来。
2. **信任纪律是护城河候选。** 事实核查不过就退回纯规则文本，这种“宁可朴素也不撒谎”的设计，在制造业买家眼里比功能多更值钱。
3. **系统中立。** 不与排程器、MES 厂商正面抢饭碗，反而可以做伙伴。
4. **架构克制。** 可剥离、可抽仓，不做清单把范围锁住了。
5. **适合封闭环境。** LLM 是可选件、规则文本兜底，意味着可以本地部署、数据不出厂——半导体客户对数据外流极敏感，这是真优势。

### 2.2 必须正视的问题

1. **零真实数据。** 仿真里“有记录”不等于真实 MES 里“有可用记录”。真实数据脏、权限难拿、安全评审周期长。
2. **验收数字验的不是价值。** 71 / 486.7 / 82.12% 是基线复现；对商业而言，对应的数字应是“归因准确率”“出报告耗时”“工程师是否敢拿去回答上司”。
3. **再演 1/12。** 反事实是最想卖的能力，也是最弱的。蓝图已设 8/12 门槛，这是对的；但它不该拖住整个产品节奏。
4. **第三方模式悖论。** 只有结果、没有决策记录时，只能给「観測帰因」；产品最硬的一档，在最需要中立的场景里用不上。
5. **用户不等于买家。** 排程负责人、值班长是用户，预算通常不在他们手里。谁出钱、为哪个损失出钱，蓝图没写。
6. **滩头堡窄、周期长。** 半导体 fab 客户数量有限、准入严格，销售周期通常以年计。
7. **度量有漏洞。** “Unknown 率是正指标”会被“全说不知道”刷高；缺少“误归因率”和“过度不明率”两个反向指标。
8. **真正的对手是现状。** 一位会写 SQL 的工程师加几个小时，以及 MES 自带报表、BI、流程挖掘类工具。差异化必须用实测证明，而不是用叙述。

### 2.3 蓝图自身的缺口

- **缺导入页。** 第三方数据的全部摩擦都在这一步，却没有对应画面。
- **缺可分享的只读报告页。** “用户验证靠它”，却只有导出按钮。
- **异常一览缺“按 lot 查”的入口。** 凌晨三点的问题多半以“lot X 为什么晚了”开头，而不是浏览排序清单。
- **品质页混了两件事。** “本厂数据有多可信”与“方法在基准上多强”是两个受众，两套口径。
- **总览与“不做通用 BI”冲突。** 建议下沉为内部页或删除。
- **严重度未定义、无案件生命周期。** 需要明确：严重度 = 影响 lot 数 × 超期时长 × 客户优先级；案件状态 = 新 / 调查中 / 已出报告 / 已交班。

* **缺排程结果视图（甘特）。** 被解释的对象——排程结果本身——没有画面。需要机台 / 批次 / 产品 / 订单四种视角，共用同一时间轴，只读，默认只显示案件窗口。
* **缺横向工具。** 时间游标、计划 vs 实绩、决策点检视器、影响传播、瓶颈热力、声明台账，见第 5 节。

## 3. 水平思考：五个换角度的选项

- **A · 把弱点变资产。** 仿真意味着“有真值”：可以注入已知故障（机台宕机、物料短缺、派工规则差异），精确衡量归因对不对。把 Trap Cases 升级为可公开的基准（Plain / RAG / ResiliTrace 三路），既是内部门槛，也是对外获信任的内容。
- **B · 换买家。** 不只卖给排程负责人，也卖给“需要对外出证据的人”：代工 / EMS 与客户之间的交期责任争议、质保的客户审核。一份中立、可验证的单件证据报告，有明确的“付费冲动”。
- **C · 把契约变协议。** 将 Evidence Schema + 三档契约开放为规范，ResiliTrace 做参考实现与校验器。若上游系统愿意输出 evidence\_refs，第三方模式就能从「観測帰因」升到「記録」，悖论得到化解。
- **D · 先卖服务再卖产品。** 固定价“异常归因诊断”PoC：用客户脱敏历史数据产出报告，既换来真实数据，也换来第一笔收入，功能优先级由 PoC 决定。
- **E · 邻近行业对照。** 同构问题出现在制药的偏差调查（要求证据与数据完整性）、汽车电子的客诉回溯（8D 类流程）里；但验证成本与领域知识完全不同，只作二期选项记录，现在不要分心。

## 4. 完整方案（我认为最稳的一套，没有“完美”，只有可验证）

### 4.1 定位微调

保留一句话与英文 tagline。增加一条可兑现的承诺：**每份报告可验证**——报告内含源数据行的哈希与导出清单，第三方可自行复核。这把“证据层”从口号变成可检查的属性。

### 4.2 产品分层

- **核心（1A/1B 必交）：** 导入 Import、异常一览 Cases（含 lot 查询）、证据 Evidence（含证据抽屉）、报告 Report（只读分享）、品质 Quality（本厂数据）、排程 Schedule（只读甘特，机台 / 批次 / 产品 / 订单四视角）。
- **Beta：** 再演 Replay。保留独立页，但导航标 Beta、默认不对外，从证据页的“在此决策点再演”进入；通过率达 8/12 前不宣传。
- **工房区（内部）：** 运行 Run；总览 Overview 只读，视情下沉。
- **新增机制：** 证据哈希；严重度定义；案件状态；逐行导入报错；时间游标、计划 vs 实绩、决策点检视器、声明台账。

### 4.3 度量体系（品质页的新骨架）

- **記録：** 引用核查通过率必须 100%。任何一句话点下去落不到原始行，按事故处理。
- **観測帰因：** 在已知真值的故障注入集上测准确率，并做置信校准（自称八成把握的，是否约八成是对的）。
- **不明：** 两个数。该说不明却硬凑 = 误归因率（红线）；有证据却说不明 = 过度不明率（黄线）。
- **效率：** “被追问”到“报告出炉”的耗时，在 PoC 里与人工基线对照。
- **再演：** 通过率 1/12 → 8/12 的门槛不变。
- **口径规则：** 每个数字带分母、数据来源（仿真 / 真实）、日期。

### 4.4 数据与部署

本地或私有云优先，数据不出厂；LLM 可选、可用本地模型，规则文本兜底。导入页提供约定 schema、字段映射、逐行报错与覆盖率预览，让客户在第一步就看到“你的数据最多能支撑到哪一档”。PoC 阶段用部署级访问控制，账号计费仍不做。

### 4.5 商业路径：四道关

- **G0 · 内部真值关：** 在仿真上跑故障注入基准，产出归因准确率与校准曲线，同时决定再演的去留；排程甘特与声明台账也在这一关用仿真数据跑通。
- **G1 · 访谈关：** 不对外宣称，但访谈 10–15 位生产技术 / 生产管理 / 质保 / IT。验证痛点频率、现有排查耗时、谁出预算、能否给脱敏数据。
- **G2 · PoC 关：** 2–3 家设计伙伴，固定价诊断，在其历史数据上出 5–10 份证据报告，由其工程师盲评“敢不敢拿去回答上司或客户”。
- **G3 · 产品化关：** 按厂 / 按年授权加部署费，渠道优先考虑 SIer 与 MES 厂商。价格与规模均为待验证假设，此处不给数字。

### 4.6 止损条件

- 访谈中没有任何一家愿意共享脱敏数据 → 回到纯基准 / 开放规范路线（选项 C）。
- 故障注入集上，観測帰因准确率与误归因率达不到自定门槛 → 暂停对外，先修引擎。
- 再演到约定日期仍低于 8/12 → 移出产品，降为内部研究。
- 商标与域名核查未过（近邻 Resilio / Resilinc / Resilire）→ 改名，不拖。

## 5. 画面设计（所有页面）

完整设计稿见同一对话中的设计页。这里是设计规则与页面清单。

**视觉语言**

- 默认深色（为凌晨三点），报告页用浅色、可打印。
- 三档契约用“形状 + 文字 + 颜色”三重编码：● 記録（实心）、◐ 観測帰因（半实心）、○ 不明（空心虚线），不靠颜色单独传达。
- 金色只给“该页唯一焦点”；证据行用等宽字体；每个数字带口径小字。
- 点任何结论 → 右侧证据抽屉展开原始行；「不明」块必须写明缺什么数据。

**页面清单（八页，另加排程页与视图工具）**

1. **導入 Import（新增）：**“我的数据最多能撑到哪一档？”
2. **異常一覧 Cases：**“哪个最急？”，顶部固定 lot 查询。
3. **証拠 Evidence ★：**“这一件为什么发生？”，一句话结论、归因时间线、迟到拆分、证据抽屉。
4. **再演 Replay（Beta）：**“当时换个做法会怎样？”，只列真实存在过的决策点。
5. **品質 Quality：**“这套解释有多可信？”，分“本厂数据”与“方法基准”两个标签。
6. \*\*報告 Report（新增）：\*\*只读分享页，浅色，带源数据哈希与口径注。
7. **運行 Run（工房）：**“跑一次会发生什么？”
8. **総覧 Overview（工房，只读）：**“厂里现在整体怎么样？”

**排程与视图工具（第二轮新增）**

| 视图 | 回答的问题 | 依赖数据 | 批次 |
| --- | --- | --- | --- |
| 排程 Schedule（甘特：机台 / 批次 / 产品 / 订单） | 什么在哪台机器上跑，异常落在哪 | 结果数据 | 必做 |
| 时间游标（控件，不是页面） | 同一时刻，厂里各处什么样 | 事件时间 | 必做 |
| 计划 vs 実績 | 从哪一刻开始偏离计划 | 计划快照 + 实绩 | 必做 |
| 決策点检视器 | 当时为什么这么派 | 决策日志 | 必做 |
| 影响传播 | 异常波及了哪些 lot、订单、客户 | 结果 + 订单关系 | 必做 |
| 瓶颈热力 | 堆积在哪台机台、哪个时段 | 事件 | 必做 |
| 声明台账 | 报告里每句话靠什么证据 | Evidence Schema | 必做 |
| 机台状态带 / Q-time 余量 / 复发帕累托 / 数据覆盖缺口 / 证据篮 | 见各自对应的问题 | 状态事件、规则、多案件累积 | 第二批 |
| 交接视图 | 上一班查到哪了 | 案件状态 | 第三批 |

筛选标准：必须能从案件进入、点击后落到证据行、回答一个真实会被问到的问题；做不到的是通用 BI，不做。缺数据时视图显示“此视图需要 X，当前缺失”，这个空态本身就是「不明」的画面。最小集建议：排程甘特、时间游标、计划 vs 实绩、决策点检视器、声明台账。

## 6. 下一步（建议顺序）

1. 本周：定义严重度与案件状态；给 Evidence Schema v0 补上哈希与三档字段。
2. 两周内：故障注入基准的雏形，先出一版准确率与校准曲线。
3. 并行：起草访谈提纲与“脱敏数据说明”；做商标与域名核查。
4. 1A 照旧推进（schema → 骨架 → 证据页），但把 Import、Report 与排程甘特（先做按机台、按批次两种视角）一并纳入；时间游标、计划 vs 实绩、决策点检视器放 1B。

## 7. 我没能验证的

蓝图中的全部数字、市场规模、竞品功能细节、定价与销售周期，我都没有核实；本文关于它们的判断是结构性推演，需要靠访谈与桌面调研来证实或推翻。
