ResiliMES-AI01 · Problemuser: fab shift lead / scheduling engineer

The user

When people on the floor can't read a schedule, they override it, and the overrides cost Q-time.

1 · Too complex

The schedule can't be read

1,313 tools, 2,156 lots and 264 Q-time limits. A tool sits idle next to a full queue, and nobody on shift can see why.

→
2 · Override

The shift lead fills the gap

The lead starts the waiting lot by hand. The idle time was often the Q-time gate keeping a downstream window from being missed.

→
3 · Loss

The Q-time window is missed

The lot misses its CQT window (1–24 h) at the next step. A missed wet-etch window sends it back for a re-clean.

Measured on our own schedule: filling every deliberate gap in a 48 h run adds +19 avoidable Q-time violations (23 → 42). The idle time was protecting something.
So the missing piece is understanding, not a new optimizer. The lead needs to see the reason behind an idle gap or a lot's position before deciding to override it.

Q-time range: docs/QTIME_URGENT.md · re-clean: docs/SMT2020_PROVENANCE.md · gap fill: docs/gap_counterfactual/seed1_48h.md (seed 1, 48 h, pure simulation)

What you can click

Bar → why here, why this tool, why now · Gap on a tool → why idle · Family window → what happened, why WIP changed · Free question.

Tier · assigned by code, never by the model

decision_record a recorded gate or dispatch decision explains it
rule_emergent only "the result of rule X in that state"
unknown the record does not say, so we say so

Refused, not softened. A rewrite that claims intent ("decided to", "chose to") on a rule-emergent answer is refused: tier_upgrade_refused. A failed fact-check, bad JSON or a provider error degrades to the scripted answer, labelled.

Remaining work · 71 avoidable misses

Mostly chained Q-time windows at the batch diffusion furnaces.

  • Gating chained windows as one cut avoidable misses to 61, but only 130–154 lots / run were completed. Rejected, off by default.
  • Next: reserve next-window capacity only for lots that will actually arrive in it.
Why this matters for the AI layer

Every miss carries a class in the study output (qtime_miss_class): avoidable, breakdown after admission, pre-gate window, tool down / PM, transport, rework.

So the AI can say which kind of miss a lot had, from the record. It does not invent a better schedule.

Classifying a miss changes its label, not the schedule.

ResiliMES-AI09 · Honesty · design evidencewhat we measured, including what didn't help

Why the AI explains instead of schedules

We tested whether the AI should touch decisions. The data says no.

Shipped exception-only trigger
0 AI calls

Published book (seed 9, 5 h): 58 exceptions, 0 escalations. All KPIs are identical to rules only. Generated stress set: 0/16 triggered (60–84 exceptions each).

Reading: rules plus the hard gate are enough. By design, the AI never touches the decisions.

Same-budget K-curve · lever search
flat

K = 1, 3, 5, 10, 15 × 3 search seeds give identical outcomes (avoidable 0, hot late 0, wt 3,323.7 min). Sim calls grow 222.7 → 1,106. Non-LLM.

Reading: there is no headroom on this book, so the AI effort goes into explanation.

B/C ordering comparisons
study mode

These run only with SHIFT_LEAD_ESCALATE=always: 16/16 stress books trigger, with 35–49 escalations each. The trigger threshold was not changed to make it fire.

Label: exploratory. They are not a claim that the LLM schedules better.

What we don't claim: that an LLM schedules better than rules. We claim that a rule schedule can be explained honestly, at the level of each bar and gap, with evidence a shift lead can check.

ResiliMES-AI11 · Safetyadvice only · bounded · labelled fallbacks

Line-side safety

The AI can't block the line, can't change the plan, and can't hide a failure.

Advice only

  • Every AI reply carries advice_only: true. No AI endpoint writes a plan.
  • Three-role deliberation (long-term plan, shift, floor), each role with only its own evidence. The deterministic kernel decides, Q-time first. Conflicts are recorded, never averaged.
  • An option that projects more Q-time violations than the rule default is infeasible and discarded.

Checked

  • Every number and id in an answer is fact-checked against a tool result.
  • The code assigns the tier. A rewrite that upgrades it is refused.
  • Evidence SQL: one SELECT, allowlisted tables, LIMIT enforced.
  • Every lever is re-simulated before it is shown as a saving.

Bounded, with labelled fallbacks

  • Time budgets: 90 s per model call, 180 s per task. A timeout falls back to the rule result, labelled timeout.
  • Other degrade reasons are also labelled: fact_check_failed, tier_upgrade_refused, bad_json, provider_error.
  • No token: "offline stand-in" badge. Tokens come from the env and are never logged.

  • check_zetaris_smt.py: row counts and hashes vs files → PARITY OK.
  • fab_ops: the recorded run, read through the SQL guard.

Meterless engines + Cursor

  • Scout Intent signs every run contract; test tests/test_scout_engine.py.
  • Markovian runs the agent loop as checkpointed chunks. World Model is the plant log.
  • H-MEM local port: 13/13 vectors.
  • Built in Cursor.
Fallbacks are always labelled. Without a Nightshift token the answer comes from a scripted stand-in and the badge says "offline stand-in". Without a Zetaris key the query line says "local extract (Zetaris not called)".
What is unusual. Most agent demos let the model decide. Here a tested scheduler decides, Scout won't run without a fresh contract, and Nemotron works where language helps: explaining.
