# ResiliTrace 品质度量口径（quality/v0）

实现：`resilimes/explain/quality.py`；契约测试：`tests/test_explain_quality.py`。
本文只定口径。口径变更 = 版本变更，不许静默改分母。

## 为什么有这一页

项目文档承诺过度量三件事——误归因率、过度不明率、置信校准——但一直没有实现，
而历史数字（1/12、11/12、8/48）分母各不相同、混在一起引用。度量落地的第一
要求是：每个比率永远带着自己的分子和分母出现，单独一个百分比不算数。

## 样本

一条评估样本（AttributionSample）记录一次归因评估：

- `tier`：系统这次回答的档位，沿用 Evidence Schema 的三档（recorded / attributed / unknown）。
- `predicted_cause`：系统给出的原因；unknown 档必须为空，其余档必须有值（模型层校验）。
- `true_cause`：评估真值——故障注入的注入原因，或评审确立的原因；无法判定时为空。
- `confidence`：系统给出归因时的置信（0–1），没有就留空，不许事后补造。

真值未知的样本不进入任何比率的分母。

## 三项度量

### 误归因率 misattribution

- 分子：给出了归因、真值已知、且 predicted ≠ true 的样本数。
- 分母：给出了归因、且真值已知的样本数。
- 含义：系统开口归因时有多大概率说错。答 unknown 的样本不在分母里——
  不开口不算说错，它记在过度不明率里。两个率必须一起看：只压误归因率，
  可以靠什么都答 unknown 作弊；只压过度不明率，可以靠乱猜作弊。

### 过度不明率 over-unknown

- 分子：真值已知、但系统答 unknown 的样本数。
- 分母：真值已知的样本数。
- 含义：在评估语境下真值可判定（即原则上可以答），系统仍然说不知道的比例。
- 注意：这测的是评估集上的过度谨慎，不是真实数据上的表现——真实 MES 数据里
  「真值可判定」的比例本身未知，本率不能外推到真实工厂。

### 置信校准 calibration

- 纳入样本：同时有 confidence、有归因、真值已知的样本；无置信样本被排除并单独计数
  （`calibration_excluded_no_confidence`），不许混进分箱。
- 呈现：10 个等宽分箱（[0.0,0.1) … [0.9,1.0]），每箱给 count、平均置信、实际准确率；
  汇总给 ECE（按各箱样本量加权的 |准确率 − 平均置信|）。
- 含义：ECE 越小，置信越「说得准」；单箱准确率与置信的差距比 ECE 总值更值得看。

## 无数据时的行为

分母为 0 的比率，value 为 None（数据不足），不报 0.0。0.0 是一个测量结论，
None 是「还没测」——把后者写成前者，正是这个项目要防的事。全体样本中答
unknown 的占比另有 unknown_share 作描述统计，它不是质量结论。

## 与既有部件的关系

- 原因词表沿用 `explain/causes.py` 的注入分类（注入基准与解释层共用同一套原因名），
  但本模块不校验词表成员：第三方模式的原因名可能来自外部系统。
- 样本从哪来由调用方负责：故障注入基准的运行结果、复演评估、人工评审集都可以
  适配成样本序列后调用 `evaluate()`。本模块不读文件、不跑仿真。
- 品质页（后续增量）直接消费 QualityReport 的 JSON 形态，不另算一套口径。
